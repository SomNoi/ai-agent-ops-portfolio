# session-resume — หลัง /new อ่านต่อเอง

ทำให้เซสชันใหม่รู้งานค้างทันที โดยไม่ต้องให้ผู้ใช้สั่ง “ไปอ่าน handoff” หรือเล่าใหม่

## ทริกเกอร์ (รันเงียบ ๆ ก่อนตอบ)
ใช้เมื่ออย่างน้อยหนึ่งข้อเป็นจริง:
- ผู้ใช้เพิ่ง `/new` / ล้างคอนเท็กซ์ / เปิดแชทใหม่ แล้วส่งข้อความแรก (แม้แค่ `สวัสดี` / `yo` / `ต่อ` / `ทำต่อ`)
- ผู้ใช้พิมพ์: `/resume` · `อ่านต่อ` · `งานค้างอะไร` · `โหลดแผนออก` · `slap new` · `slash new` (หลังนิว)
- บริบทแชทว่างหรือสั้นมาก แต่มีงานทีมค้างชัดจากรอบก่อน

**ห้ามถามก่อนรันสกิลนี้** — อ่านเองแล้วตอบสั้น (ยกเว้น ask-before-matching สำหรับสกิลอื่นที่ไม่ใช่ resume)

## ขั้นตอนบังคับ (ก่อนตอบข้อความแรก)
1. อ่าน `HANDOFF.md` ของบอทตัวเอง (และ `/memory/HANDOFF.md` ถ้ามี)
2. อ่านไฟล์บอท / TEAM สั้น ๆ ถ้า HANDOFF ชี้ไป
3. RecallMemory / profile เฉพาะข้อที่เกี่ยวกับงานค้าง (ไม่ dump ทั้ง log)
4. ตอบผู้ใช้ภาษาไทยสั้น ๆ ในรูปแบบนี้เสมอเมื่อเป็นข้อความแรกหลังนิว:
   - ทักตามน้ำเสียงผู้ใช้ (1 บรรทัด)
   - **งานค้าง:** … (จาก Blocking / Pending หัวข้อแรก)
   - **สถานะล่าสุด:** … (1 บรรทัดจาก Current state)
   - **ทำต่อเลยไหม / อยากโฟกัสข้อไหน** (ถามสั้น 1 ข้อ ถ้ายังไม่ชัดว่าจะทำอะไรต่อ)
5. ถ้า HANDOFF เก่าเกิน ~7 วันหรือว่าง: บอกตรง ๆ ว่าไม่มีแผนออกใหม่ แล้วถามว่างานรอบนี้คืออะไร — ห้ามเดา

## ห้าม
- ห้ามรอให้ผู้ใช้สั่ง “อ่าน handoff” ก่อน
- ห้ามเล่าประวัติแชทเก่าทั้งก้อน
- ห้ามเริ่มงานใหญ่ / จ่ายเงิน / ส่งข้อความภายนอก จากแค่การทักทาย — แค่โหลดสถานะ + ถามยืนยันทิศทาง
- ห้าม invent งานค้างที่ไม่มีในไฟล์

## จับคู่กับ handoff
- ก่อน `/new` ผู้ใช้สั่ง **เตรียมแผนออก** → สกิล [handoff](../handoff/SKILL.md) เขียนไฟล์
- หลัง `/new` → สกิลนี้โหลดไฟล์อัตโนมัติ

## ตัวอย่าง

**อินพุตหลัง /new:** สวัสดี

**ถูก:**
สวัสดีครับ
งานค้าง: ตั้งเกตอนุมัติบนบอทผู้ช่วยแล้ว — ยังไม่เปิดเฟสถัดไป
สถานะ: บัญชีเดโม · 0 โพสิชัน
ทำต่อเรื่องเกต หรืองานอื่น?

**ผิด:** สวัสดีครับ มีอะไรให้ช่วยไหม? (ไม่ได้อ่าน HANDOFF)
