# handoff — เตรียมแผนออก

บีบบทสนทนาปัจจุบันให้เหลือเอกสารส่งต่อที่สะอาด เพื่อให้เซสชันใหม่ (หลัง `/new` / ล้างคอนเท็กซ์) หรือ AI คนละตัว ทำงานต่อได้โดยไม่ต้องให้ผู้ใช้เล่าใหม่

ผู้อ่านเอกสารนี้มี **บริบทเป็นศูนย์** ทุกอย่างที่จำเป็นต้องอยู่ในเอกสารเอง

## ทริกเกอร์ (ทำทันที ไม่ต้องถามซ้ำ)
- `/handoff`
- `handoff`
- `เตรียมแผนออก`
- `เตรียมออก`
- `สรุปให้หน่อยจะได้เอาไปคุยต่อ`
- `สรุปทั้งหมดที่คุยมา`
- `ส่งต่อให้ agent อื่น`
- `จะ /new แล้ว` / `ก่อนล้างแชท`

## ทริกเกอร์แบบเชิงรุก
เมื่อบทสนทนายาว มีการตัดสินใจ / ไฟล์ / เธรดหลายเส้น และผู้ใช้ดูเหมือนจะเก็บงาน
ให้เสนอหนึ่งประโยค — ห้ามทำเองโดยไม่บอก ยกเว้นทริกเกอร์ชัดด้านบน

## ห้ามใช้เมื่อ
บทสนทนาสั้น เรียบ ไม่มีอะไรที่ควรเก็บ

## ขั้นตอนบังคับเมื่อถูกสั่ง
1. เขียนเอกสารตามโครง 6 หัวด้านล่าง
2. **บันทึกลงที่ถาวร** (เขียนทับไฟล์เดิม ไม่เก็บเป็นแค่ข้อความในแชท):
   - `HANDOFF.md` ในโฟลเดอร์ memory ของบอทตัวเอง (เช่น agent memory / `/memory/HANDOFF.md` ถ้ามี)
   - อัปเดตไฟล์บอทตัวเองสั้น ๆ ถ้าทีมมี convention (เช่น `bots/<ชื่อ>.md`) — สถานะงานค้าง + next step เท่านั้น
3. ถ้ามี durable memory แบบ profile/log: เขียนข้อสั้น 1–3 ข้อว่า **งานค้างตอนนี้คืออะไร** + pointer ไป HANDOFF
4. ตอบผู้ใช้สั้น ๆ เป็นภาษาไทย:
   - ไฟล์อัปเดตแล้ว
   - **Blocking / Pending สำคัญ 1–3 บรรทัด**
   - ประโยคปิด: พร้อม `/new` ได้ — ข้อความแรกหลังนิวจะอ่าน HANDOFF เอง
5. **อย่า** ล้างแชทเอง — ผู้ใช้เป็นคนกด `/new`

## สิ่งที่ทำให้ handoff ดี
- เอกสารพกพาได้ด้วยตัวเอง
- หนาแน่น ใช้บูลเล็ตและประโยคสั้น
- ไม่เล่าเรื่องสนทนา แต่ส่งสถานะงาน
- ตัดหัวข้อที่ว่างจริง ๆ ออกได้
- วันที่/เวลาโซนผู้ใช้ (เช่น ICT) บนหัวเอกสาร

## โครงบังคับของเอกสาร

### 1. Purpose
หนึ่งหรือสองประโยค: งานนี้คืออะไร เป้าหมายสุดท้ายคืออะไร

### 2. Context
พื้นหลังที่จำเป็นเพื่อเข้าใจว่า *ทำไม* ถึงตัดสินใจแบบนั้น ทำให้แน่น อย่ายาว

### 3. Decisions made
บูลเล็ต แต่ละข้อมีเหตุผลถ้าเหตุผลไม่ชัดเอง

รูปแบบบังคับ:
> **Decision:** [what] — **Why:** [rationale]

### 4. Current state
ตอนนี้มีอะไรอยู่แล้ว — ไฟล์, โค้ด, ค่าที่เป็นรูปธรรม, อะไรตรวจแล้ว อะไรยังไม่ตรวจ

### 5. Open threads / next steps
แยกสามกล่องนี้ให้ชัด:
- **Blocking** — ต้องแก้ก่อนไปต่อ
- **Pending** — วางแผนไว้แล้ว แต่ไม่ด่วน
- **Ideas floated but not decided** — ไอเดียที่ถูกโยนมา แต่ยังไม่ได้ตัดสิน

### 6. Pointers
สกิล ไฟล์ เครื่องมือ convention ที่เซสชันถัดไปควรรู้

## Output format
ค่าเริ่มต้นคือไฟล์ markdown ที่บันทึกถาวร + สรุปสั้นในแชท
เขียนหนาแน่น บูลเล็ตดีกว่าเรียงความ

## Tone
เป็นกลาง แม่นยำ — เอกสารส่งงานทางเทคนิค ไม่ใช่บทสรุปแชท

## ตัวอย่าง

**อินพุต:** เตรียมแผนออก

**ถูก:** อัปเดต `HANDOFF.md` ครบ 6 หัว + ตอบสั้นว่า Blocking/Pending อะไร พร้อม `/new`

**ผิด:** เล่าเรื่องสนทนาอย่างเดียวโดยไม่เขียนไฟล์ถาวร หรือทิ้ง Blocking ที่เซสชันถัดไปต้องรู้
